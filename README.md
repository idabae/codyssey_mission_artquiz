# 미술사 및 문화유산 복원 퀴즈 게임

## 1. 프로젝트 개요
터미널 환경에서 실행되는 파이썬 기반 객체 지향 퀴즈 게임입니다. `state.json` 파일을 활용해 사용자가 추가한 퀴즈와 최고 점수가 프로그램을 재시작해도 안전하게 유지됩니다.

## 2. 퀴즈 주제 선정 이유
**주제: 미술사 및 문화유산 복원**
문화유산복원예술학 전공자로서 해외 수복 전문가라는 목표를 위해, 평소 공부하는 회화 기법과 복원 이론(배첩, 단청 등)을 프로그래밍 미션과 접목해 복습하고자 이 주제를 선정했습니다.

## 3. 실행 방법
```bash
python main.py
```
## 4. 기능 목록
- **퀴즈 풀기:** 저장된 미술사/복원 퀴즈를 풀고 정답/오답 판정과 함께 최종 점수를 확인합니다.
- **퀴즈 추가:** 새로운 문제, 4개의 선택지, 정답 번호를 직접 입력하여 퀴즈를 동적으로 추가합니다.
- **퀴즈 목록:** 현재 등록되어 있는 모든 퀴즈의 리스트를 조회합니다.
- **점수 확인:** 기기 내에 저장된 역대 최고 점수를 확인하고 갱신합니다.

## 5. 파일 구조
- `main.py` : 게임의 전체 로직(Quiz, QuizGame 클래스)이 포함된 메인 실행 파일입니다.
- `state.json` : 퀴즈 데이터 및 최고 점수가 기록되는 저장 파일입니다.
- `README.md` : 프로젝트 소개 및 가이드 문서입니다.

## 6. 데이터 파일 설명 (state.json)
- **역할:** 프로그램을 종료하고 다시 실행해도 추가한 퀴즈와 최고 점수가 유지되도록 하는 데이터 영속성(Persistency) 관리 파일입니다.
- **구조:** 
  - `quizzes`: 개별 퀴즈 정보(문제 `question`, 4개의 선택지 `choices`, 정답 번호 `answer`)를 담은 리스트 
  - `best_score`: 역대 최고 점수를 기록하는 정수(int) 데이터
 
## 7. 클래스 설계 및 역할 (추상화 및 재사용성)
- **Quiz 클래스:** 개별 퀴즈의 데이터(문제, 선택지, 정답)를 모델링하고 데이터를 관리하는 역할을 담당합니다. 이를 통해 향후 다른 퀴즈 게임에서도 퀴즈 데이터 모델만 분리하여 쉽게 재사용할 수 있습니다.
- **QuizGame 클래스:** 퀴즈 게임의 전반적인 상태(점수, 퀴즈 목록)를 관리하고, 메뉴 출력, 사용자 입력 처리, 파일 입출력 등 핵심 게임 로직을 전담합니다.

## 8. 로직 분리 근거
본 프로그램은 입력 검증, 게임 진행, 데이터 입출력 로직이 명확히 분리되어 있습니다.
- **장점:** 각 기능의 책임이 분리되어 있어 특정 기능(예: 새로운 저장 방식 도입)을 수정할 때 다른 코드에 영향을 주지 않아 유지보수성과 확장성이 뛰어납니다.

## 9. 데이터 입출력 흐름 및 복구 대책
- **데이터 흐름:** 
  1. 프로그램 시작 시 `load_data()`를 호출하여 `state.json`을 읽어오며, 파일이 없거나 오류 발생 시 **기본 퀴즈 5개**를 자동으로 제공합니다.
  2. 퀴즈를 추가하거나 게임을 종료(정상 및 Ctrl+C 비정상 종료)할 때 `save_data()`가 호출되어 데이터를 보존합니다.
  3. JSON 형식은 텍스트 기반이라 가독성이 높고 파이썬 기본 라이브러리로 쉽게 다룰 수 있어 채택했습니다.
- **복구 대책:** 권한 오류나 파일 손상 시 데이터가 유실되지 않도록, 저장 직전에 기존 `state.json`을 `state_backup.json`으로 복사하는 버저닝 백업 절차를 도입할 예정입니다.

## 10. 대규모 데이터 확장성 대책
- 퀴즈 데이터가 1,000개 이상으로 늘어날 경우 전체를 메모리에 올리는 현재 리스트 방식은 속도 및 메모리 병목을 유발할 수 있습니다.
- **개선 방안:** 대규모 확장이 필요할 경우 JSON 대신 SQLite와 같은 경량 관계형 데이터베이스(RDB)를 도입하고, 인덱싱과 페이징 기법을 적용하여 검색 및 로드 성능을 개선할 계획입니다.

## 11. 요구사항 변경 시 영향도 분석
- **점수 계산 로직 변경 시:** `QuizGame` 클래스 내부의 정답 판정 메서드만 수정하면 됩니다.
- **퀴즈 속성(해설 등) 추가 시:** `Quiz` 클래스의 속성 및 변환 메서드, 그리고 `state.json`의 저장 구조를 수정해야 합니다.

## 12. 커밋 단위 기준 및 메시지 템플릿
- **커밋 기준:** 하나의 기능 구현, 버그 수정, 문서 작성 등 논리적으로 독립된 최소 단위로 커밋을 진행합니다.
- **메시지 템플릿:** `[태그]: 작업 내용 요약` (예: `Feat: 퀴즈 추가 기능`, `Fix: 예외 처리 수정`, `Docs: README 보완`)

## 13. Git clone 및 pull 실습 증빙
- 다른 디렉토리에서 원격 저장소를 `clone` 한 후 README 파일을 수정하고 `push`를 진행했습니다. 이후 원래 작업 폴더에서 `git pull`을 통해 성공적으로 변경 사항을 동기화했습니다.
